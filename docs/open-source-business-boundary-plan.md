# AI-Skill-Evaluator 开源与商业边界规划 V1.0

> 2026-08-25 ｜ 纯战略规划，零代码改动 ｜ 核心问题：开源可信度 vs 商业空间的边界怎么划

---

## 结论先行

# ✅ MIT License 可以继续用，不需要改。商业护城河不在代码，在"数据资产 + 内容品牌"。当前阶段（0 星仓库、无用户）谈商业化为时过早——未来 3 个月唯一任务是攒真实测评数据和维护者信誉。

---

## 1. 开源边界建议（Public 仓库长期公开的内容）

| 内容 | 公开判定 | 理由 |
|---|---|---|
| 核心 CLI（评分引擎/pricing/security/runs） | ✅ 永久公开 | 开源是信任的唯一来源；评测工具闭源=结论不可信，项目就死了 |
| 基础评分框架与 INCONCLUSIVE 门控 | ✅ 公开 | 方法论透明是差异化卖点（对照 skills.sh 的"popularity is not review"） |
| 基础安全检测规则 | ✅ 公开 | 规则公开反而促进社区提交新规则，形成众包情报网 |
| 文档/示例/验证报告方法论 | ✅ 公开 | 传播即获客 |
| **通用种子题库**（W3 计划的 20 题） | ✅ 公开 | 题库公开才有社区贡献，网络效应从这里长出来 |

**原则：所有"能力"公开。工具越有用、越透明，用户越多。**

## 2. 私有资产规划（建议建 `AI-Skill-Evaluator-Private`，但**不是现在**）

### 资产分类

| 资产 | 归属 | 理由 |
|---|---|---|
| **行业深度评测集**（医疗/金融/法律等垂直领域题库，含判官校准数据） | 🔒 私有·未来核心资产 | 这是未来收费服务的产品本体；通用题库公开引流，垂直题库私有变现 |
| **历史测评数据库**（累计 runs 数据、跨模型对比、时间序列） | 🔒 私有·核心资产 | "我们测过 500 个 skill 的三个月漂移曲线"是无法从开源代码重建的数据壁垒 |
| **判官校准数据**（judge 一致性实验记录） | 🔒 私有 | 多 judge 共识的调参依据 |
| 商业方案/定价 | 🔒 私有 | 显然 |
| 三轮验证报告（已公开的 R1-R3） | ✅ 保持公开 | 已发布的方法论背书，撤回伤信任 |
| testbed 四个 skill 的 evals.json | ✅ 保持公开 | 可复现性承诺的一部分 |

### 时机判断：**现在不建私有仓库**

理由：①还没有任何值得保护的垂直数据——先有产出再有保险箱；②过早建私有仓会诱导"好东西藏起来"的习惯，侵蚀开源节奏。触发条件：**第一份行业深度评测集开始制作时**（约与首个付费意向同时）。

## 3. 商业化方向分析（按定位匹配度排序）

| 方向 | 匹配度 | 分析 |
|---|---|---|
| **专业评测报告**（单 skill 深测，交付六维+安全+成本报告） | ★★★★★ | 与现有 CLI 能力 100% 重合，边际成本≈一次运行的 token 钱；skill 作者付费动机明确（上架前自证）；也是频道内容素材 |
| **企业 Skill 准入审计**（团队引入第三方 skill 前的安全+效果审计） | ★★★★☆ | 安全扫描+基线对比正是企业刚需；需要 SLA 和责任界定，放中期 |
| **垂直行业评测集授权** | ★★★☆☆ | 依赖 §2 私有资产的积累，远期 |
| 云端评测 SaaS | ★★☆☆☆ | 与 Non-goals 冲突（local-first 是卖点）；仅在用户强烈要求时作为托管跑批服务考虑，不做平台 |
| 广告/推荐位 | ❌ 不做 | 测评收钱改结果 = 自杀 |

**红线写死：评测结论永远不可售卖。"付钱得 PASS"一次就会杀死整个项目。**

## 4. 知识产权与开源风险分析

### MIT 影响（实测核过 LICENSE）

1. **任何人（包括竞争对手）可以拿这份代码做商业产品且无义务回馈** ——这是事实，接受它。对策：护城河放在数据与品牌（§2），代码本来就不是壁垒。
2. **原作者关系**：上游 agent-skills-eval（Rishabh Mehan，MIT）已在 README/LICENSE 双处署名保留——合规义务已履行。注意：若未来上游恢复活跃并大幅演进，rebase 成本上升；应对：我们的新增模块（pricing/scoring/security）都是独立文件，冲突面小。
3. **二次开发注意**：本项目自身的 MIT 允许他人 fork 后闭源商用——同理接受。
4. **品牌保护建议**：
   - 立即在 GitHub 注册同名组织/仓库占位已完成 ✅
   - npm 包名 `ai-skill-evaluator` 已在 package.json 占名（未发布）——**npm 发布前名字可能被抢**，这是近期唯一实际的品牌风险点
   - 未来商业化时再考虑商标注册（现在太早）

## 5. 未来一年路线

### 短期 0–3 个月：只验证用户价值，不碰商业化
- 发首批 4 篇实测报告 + 社区投放（已有计划）
- 种子题库 v0（20 题）+ 雷达图/MD 导出
- **指标**：star>50、首批外部 issue、至少 1 个陌生人复现成功
- 同步启动频道内容（tdd 篇），工具与内容互相导流

### 中期 3–6 个月：数据资产开始积累
- 累计 ≥50 个 skill 的测评数据 → 私有数据库成型
- 视反馈决定：多 judge 共识 / MCP 支持
- 出现第一个自然付费询问 = 商业化绿灯信号；届时启动行业评测集

### 长期 6–12 个月：轻商业化试水（仅在信号出现后）
- 专业评测报告服务（按次收费，报告模板公开、深测私有）
- 企业审计试点 1–2 单
- 若无信号：继续纯开源 + 频道运营，无沉没损失

## Stop-Escalation 检查

- License 是否不适合未来方向？**否**——MIT 对"工具开源+数据变现"模式完全兼容（参考 PostHog/Sentry 的 open-core 前身路径）
- 开源策略重大风险？**否**——唯一的结构性代价（竞品可白嫖代码）已被数据护城河策略对冲
- 商业空间不足？**现阶段不足但不构成停止条件**——0 用户阶段本就不该有商业空间；路线图已把商业化严格 gating 在需求信号之后

无需停止扩展；本规划本身即为边界文档，后续任何商业化动作须回查本文红线（评测结论不可售卖）。
